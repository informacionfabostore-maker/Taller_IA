# Reflexión y cierre

1. Zero-shot dio una primera estructura, one-shot ayudó a reproducir un patrón concreto y few-shot mantuvo reglas comunes entre varios casos.
2. Definir esquema/reglas antes de generar reduce categorías inventadas, IDs repetidos y tipos incorrectos; permite validación automática.
3. La validación programática revisa duplicados, rangos, categorías, ciudades, fechas y tipos que pueden pasar inadvertidos en lectura visual.
4. Separar JSON, JavaScript y presentación facilita corregir datos, lógica y diseño de forma independiente.
5. localStorage persiste únicamente en el navegador, puede borrarse y no sincroniza usuarios; una base de datos real necesita servidor, autenticación, permisos y copias de seguridad.
6. Para producción se requieren backend, inventario transaccional, pagos seguros, privacidad, autenticación, logística, monitoreo, accesibilidad auditada y contenidos comerciales verificados.

## Lista de comprobación
- Landing semántica y responsive, siguiendo la referencia visual; se puede abrir `index.html` directamente.
- Imágenes generadas con ChatGPT para cabecera, productor, destacados y cada una de las 35 fichas.

- Gráfico de cantidades por categoría como bonus.
